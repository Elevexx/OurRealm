- **INCREMENT A — Media Sound Selector (original Phase 3)**: compact Sound browser (Music/Podcasts/FX, genre, mood, search, preview), attach eligible Sound to images/videos via can_reuse() + permission_snapshot(), replace original video audio, no-audio option, trim/volume/fade.
- **INCREMENT B — Quick Fire Foundation**: main Fire tap opens compact Quick Fire slider popup (default 1🔥, Newbie fixed at 1🔥, server-authoritative max range, no charge until confirm, idempotent); arrow/chevron ("Open full Fire Power controls") opens existing expanded picker. ONE Fire engine/service/ledger for both.
- **INCREMENT C — Sound-Player Fire**: Fire controls (icon + total + quick slider + expand arrow) on EVERY canonical Sound player surface (Sounds page, cards, detail, feeds, profiles, realms, playlists, persistent player, portals/nexus/worlds, search, hashtags, saved). ONE canonical Fire total per Sound; state syncs across mounted surfaces; respects privacy/blocks/moderation/deleted/suspended/fire-pause.
- **INCREMENT D — Personal Playlist Foundation**: "Add to Playlist" action everywhere Sounds appear (original OurRealm design, no platform copying); compact popup (add to existing/multiple, see membership, remove, create+name+visibility); playlists independent of widgets/realms; DB-level duplicate-entry prevention; Account Settings "Manage Sound Playlists" section (full CRUD, artwork, visibility, reorder, archive/restore, default, realm connect/disconnect, loop/shuffle/start, unavailable-sound handling, durations, usage view). Deleting playlist never deletes Sounds.
- **INCREMENT E — Sound Admin Foundation**: /admin/sounds "SOUNDS CONTROL CENTER" (existing admin auth+roles, audited): dashboard with 24h/7d/1m/all-time UTC period filters, metric cards + charts (uploads, plays, listeners, fire, playlists, reuse-by-surface, categories, AI vs non-AI, copyright, processing failures — accessible, no color-only, honest empty/error states); searchable/sortable/paginated Sound tables with extensive filters + row actions (view/edit/categorize/pause/suspend/restore/reuse controls/reports/copyright/notes/notify/reprocess). Admin actions must never fabricate rights/AI disclosures, transfer ownership silently, erase audit history, or falsify organic analytics.
- **AI Sound Classification** (part of E): separate fields — PRIMARY CATEGORY (Music/Podcast/FX) + AI GENERATION STATUS (not-marked/fully/partially/unknown) + tool, disclosure+timestamp, review status, voice-likeness; admin toggles for AI discovery section, required disclosure, chart/promo eligibility, impersonation reports. Never represent AI audio as copyright-free/cleared/original.
- **INCREMENT F — Taxonomy & Discovery**: Genre Manager + Mood Manager (separate concepts; add/edit/reorder/enable/merge with safe migration, aliases, parent/child, per-taxonomy analytics, no unsafe deletion); Sounds-page Layout Manager (config records not code: sections, order, titles, counts, desktop/mobile, draft→preview→validate→publish, version history, rollback, safe fallback); Top/Trending/Featured + charts with configurable ranking inputs (plays, listeners, fire, unique senders, playlist adds, completion, saves, growth, velocity, penalties, window) — auditable, deterministic, versioned, explainable; organic vs admin-featured vs sponsored placement always distinguished.
- **INCREMENT G — Copyright Tool**: intake (user reports, rights-holder notices, email, support, admin discovery, all surfaces), full case records (claimant, statements, e-signature, evidence, status, assignee, audit history), configurable statuses (New→…→Resolved/Rejected/Duplicate), admin actions (disable playback, disable reuse, remove from discovery/posts/playlists/contexts, mute video, preserve evidence, contact uploader, counter-notice, restore, restrict repeat uploaders, escalate, export) — every action logged; NOT an automatic determiner of ownership/infringement/fair-use. Repeat-infringement records with configurable, reviewed enforcement (no auto-ban by report count).
- **Sound Upload Rights Flow** (fits G/E): rights checkbox (unchecked default, stored with timestamp + Terms version, not legal proof), separate AI disclosure; legacy Sounds labeled "LEGACY — CONFIRMATION NOT COLLECTED", never fabricated.
- **INCREMENT H — Remaining original roadmap**: Media Studio, Realm Audio Context, Soundscape playlist widget, group realm/portal/nexus/world integration, full moderation + migration review.
- **INCREMENT I — Final verification & deployment review**: full regression, security tests, migration dry-runs, screenshots, real-device verification, performance, accessibility, rollback review, deployment approval request.

## Cross-cutting rules (all increments)
- Canonical Sound architecture only: one canonical post, one Fire total, one play total, one playlist system, one rights record per Sound. Surface-specific usage stored as relationship records.
- All permissions enforced server-side; client state never trusted.
- Audit records (admin, action, target, reason, before/after, timestamp, case id, request id, environment) — not editable via ordinary admin UIs.
- Idempotency on all mutations (Fire, publish, playlists, migrations, notifications, accounting).
- Testing requirements per founder's §20 (Quick Fire, Sound-player Fire, Playlists, Admin, device/browser matrix; simulated-viewport testing labeled separately from real-device).
- Backlog also: JWT_SECRET rotation (P2), CORS scoping (P2), mini profile hover-card (P2).
